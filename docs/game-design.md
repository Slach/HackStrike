# HackStrike — Game Design Document

> Статус: v1.0, зафиксировано 2026-11-14 по итогам дизайн-сессии с автором.
> Документ — источник истины для реализации. Изменения — только через новые
> решения автора (фиксировать в «Журнале решений» в конце).

## 1. Концепция

Браузерная сессионная командная FPS-игра, где **хакер — отдельный класс с
настоящей мини-ОС**. В отличие от Dystopia (3D-киберпространство) здесь
hacker view — **системная симуляция сети**: у каждого кибер-устройства своё
«железо» (CPU/NPU/RAM/NET), программы — это процессы с очередями, а взлом
воздействует на физический мир через контроллеры. ДНК: Uplink / Quadrilateral
Cowboy поверх аренa-шутера.

**Формула:** `(арена-шутер на фраги) + (симулятор сети в реальном времени) + (физические ловушки как гейты)`.

Ключевые отличия от референсов:
- никаких аватаров в киберпространстве — PvP хакеров это **дуэль процессами** (trojan vs antivirus, firewall vs portscan);
- сеть — **геометрия карты** (кабели можно перерубить ножом);
- данные — **лут-рецепты**: чертёж замка + compiler = эксплойт (в полной версии).

## 3. Боевой слой (meatspace)

### 3.1. Классы (v0-баланс, править по плейтестам)

| Класс | Оружие | HP | Скорость | Особенности |
|---|---|---|---|---|
| Снайпер | Bolt-винтовка (hitscan, авто-зум ×2) | 100 | 5.5 м/с | ваншот всех, кроме heavy (2 выстрела); стреляет только в зуме |
| Автоматчик | AR, полный авто | 125 | **6.5 м/с (самый быстрый)** | универсал |
| Heavygun | Minigun, раскрутка 0.5 с | 200 | 4.5 м/с | танк, медленный |
| Хакер | Пистолет (полуавто) + нож | 100 | 6.0 м/с | **нож перерубает кабель с 1 удара**; дека у терминала |

TTK ориентир: **~1.5–2 с** при полном контакте (правка 2026-11-14 после плейтеста: автоогонь + магнитизм дают почти 100% попаданий, прежние 0.5–1 с ощущались «одним выстрелом»). Оружие v1-числа (сервер валидирует скорострельность):

| Оружие | Урон | Темп | Дальность/примечание |
|---|---|---|---|
| Bolt-винтовка | **150** | 1 выстр/1.2 с | ваншот 100/125 HP, heavy — 2 выстрела; **авто-зум ×2**: включается сам через 0.1 с после появления врага в поле зрения (~25°), держится 1 с после пропажи; без зума снайпер не стреляет (клиентский гейт) |
| AR | 10 | 8 выстр/с | hitscan, малый разброс |
| Minigun | 7 | 12 выстр/с | 0.5 с раскрутка (спин-ап держится 1 с) |
| Пистолет | 18 | 3 выстр/с | полуавто |
| Нож | 60 | 1.2 удар/с | melee 1.5 м; режет кабели (см. кибер-слой) |

Зон урона (хедшоты) нет — тело единое (решение 2026-11-14). Попадания
отображаются: хитмаркер-крест у прицела, вспышка в точке, красная виньетка
при потере HP, HP-бар над игроками. Респаун — кнопка (крупная) или SPACE.

### 3.2. Управление и автоогонь (вариант B)

- WASD — движение (относительно взгляда), мышь/тачпад — mouse look (pointer lock).
- **Автоогонь**: оружие стреляет само, когда курсор на цели — без клика.
  Целиться и вести цель должен сам игрок. **Мягкий bullet magnetism**: сервер
  засчитывает попадание, если цель в конусе ~2° от заявленного направления и
  есть LOS. Доворачиваются пули, а не прицел.
- Space — интеракция (двери, терминалы, сейфы). Отдельного прыжка в MVP нет
  (этажи — лестницы с autostep 0.55 м).
- Инверсия вертикали мыши — опциональная настройка на join-экране (клиентская,
  localStorage, `hs.invertY`); на протокол не влияет.
- Переключение оружия — потом (хакеру: пистолет доступен только offline от деки).

### 3.3. Раунд, респаун, победа

- Матч: первая команда до **50 фрагов** или **10 минут** (по счёту на момент конца).
- Респаун: индивидуальный, **5 с**, на своей базе, класс можно сменить.
- Friendly fire ON (урон и ловушки бьют своих).
- Носитель сейфа: ×0.5 скорости; при смерти сейф падает на землю.

## 4. Миникарта и информация

- Видно: живые союзники (их FOV), захваченные командой камеры/датчики.
- Выстрел врага → стрелка-пеленг на 2 с.
- Кибер-карта (в hacker view): только устройства, обнаруженные своим portscan.
- Общая команда-vision считается на сервере.

## 5. Кибер-слой (hacker view)

### 5.1. Модель устройства

Каждый кибер-объект (включая деку хакера) — хост с характеристиками:

| Ресурс | Ед. | Роль |
|---|---|---|
| CPU | TFLOPS | обычные программы; скорость = доля CPU у процесса |
| NPU | PFLOPS | AI-задачи: нетривиальный поиск, подбор паролей «по словарю», анализ |
| RAM / PMEM | слоты/ГБ | делится между CPU и NPU; PMEM переживает смерть хакера, RAM — нет; ограничивает кол-во одновременно запущенных программ |
| NET | МБ/с на интерфейс | проводные/беспроводные каналы; скорость сканов и rsync зависит от узкого места маршрута |
| UI | — | у каждого устройства свой: камера = картинка + действия, дека = терминал + HUD-графики загрузки CPU/NPU/RAM/NET |
| CONTROLLERS | — | воздействия на физический мир (выключатели, приводы) |

**Планировщик: честные очереди.** Программы делят CPU/NPU тайм-слайсами:
запустил 5 сканов — каждый идёт в 5 раз медленнее. Загрузка видна на графиках
деки — графики сами становятся геймплеем (перегрузил хост — всё тормозит).
Сервер считает это дёшево (дискретные доли производительности, без потоков).

### 5.2. Программы (v0-список)

Хакерские:
- `portscan` — обнаружение устройств и портов; скорость = NET (узкое место маршрута) × ширина охвата;
- `vulnscan` — перебор уязвимостей через CPU/NPU, включая подбор паролей (мощный NPU = уточнение по словарю вместо тупого брутфорса);
- `trojan` — RCE: запуск своих программ на чужом хосте. Уровни: **userland → kernel → firmware** (kernel = скрыт от обычного ps, firmware = переживает перезагрузку/антивирус дольше). В MVP только userland;
- `watcher` — триггеры на события сети («другой хакер вошёл в устройство», «кабель перерубили»); после смерти хакера триггеры гаснут, но **переподключаются быстро**;
- `crypt/decrypt` — шифрование/расшифровка данных, скорость = CPU/NPU от объёма;
- `firewall` — фильтрует доступ по NET-интерфейсам;
- `antivirus` — мешает установке trojan, может быть пробит (гонка версий).

Обычные:
- `rsync` — копирование данных между устройствами (через NET);
- `data analyzer` — извлечение смысла из данных (NPU);
- `compiler` — **отложено**: в видении автора это инструмент NPU для создания
  новых программ из данных (например, чертёж замка → эксплойт контроллера).

### 5.3. Данные как лут

- `data` — не программа, а **данные**: пароли, чертежи замков, документы.
- MVP-рецепт: `сейф → rsync → decrypt → готовый пароль замка`.
- Полная версия: чертёж + `compiler` (NPU) = кастомный эксплойт/ключ.
- Незасейвленное в PMEM теряется при смерти хакера.

### 5.4. Hacker view UX

- Вход: только у **терминала** или в радиусе **радио-точки** (провод — мгновенно, радио — теряет скорость NET).
- Выход: **CTRL+ALT+DEL** (win/linux) / **CMD+ALT+DEL** (macOS). Тело стоит у терминала беззащитное.
- Интерфейс — **тайловый оконный менеджер**:
  - F1 = UI своей деки (терминал, графики CPU/NPU/RAM/NET, запущенные программы, PMEM-инвентарь данных);
  - F2, F3… = UI подконтрольных устройств;
  - CMD+T — новый таб, CMD+1/CMD+0 — переключение табов, CMD+H — сплит по горизонтали, CMD+V — по вертикали;
  - программы запускаются клавишами 1/2/3 и через UI;
  - в будущем — группировка UI как в window managers.
- Кибер-миникарта: карта обнаруженных устройств и связей (туман войны до portscan).
- Реализация: DOM-оверлей поверх Babylon-канваса (терминальная CRT-эстетика, зелёный на чёрном).

### 5.5. Смерть хакера

- Захваченные устройства и трояны **остаются** (они в сети, не в голове).
- RAM деки (незасейвенное) теряется, PMEM — нет.
- Watcher-триггеры гаснут, но переподключаются быстро после респауна.

### 5.6. Дека

- Пресеты на старте + кастом: «Сканер» (NET+CPU), «Брутфорсер» (NPU), «Стелс» (RAM под trojan+watcher).
- Апгрейды деки по ходу геймплея (позже — уточнить источник апгрейдов: лут/фраги/данные).

## 6. Сеть как геометрия

- Устройства связаны **физическими кабелями** (видны в мире как жгуты вдоль стен/пола).
- **Кабель можно перерубить**: нож хакера (1 удар), пули, взрывы. Обрыв =
  устройства за кабелем недостижимы по этому маршруту. Контр-хакинг доступен
  бойцам без деки: «не можешь взломать — перережь».
- **Switch** — узел коммутации: захватив, можно изолировать ветку сети.
- **Радио-точки** — беспроводной джек-ин в радиусе R (затухание сквозь стены —
  в полную версию; MVP просто радиус).
- Все устройства **нейтральные**: терминалы, точки, камеры — взламываются всеми.
  Владение = последний взломавший. Захваченный терминал можно залочить или
  читать лог подключений.

### 7.1. Физический сейф-эвакуация

- Сейфов на карте **несколько**.
- Физический сейф не в сети: подойти, space → взять (×0.5 скорости),
  дотащить на свою базу → **+10 фрагов команде** + содержимое (данные).
- Носитель роняет сейф при смерти. Открыть на месте нельзя (нужна база).

## 8. Карты

- MVP-карта: 12–16 комнат, 2 этажа (лестницы с autostep), зеркальная
  симметрия, нейтральная сеть.
- Терминалы: 2 проводных + 1–2 радио-точки на contested-позициях (не на спавнах).
- Стиль: воксель-киберпанк (циан/маджента на тёмном), hacker view — CRT-терминал.
- Будущее: редактор карт (формат карты — данные, см. архитектуру).

## 9. Архитектура реализации

### 9.1. Общий контур

- **Сервер (Go)** — единственный источник истины: движение, урон, симуляция
  кибер-слоя (дискретно, в тик 30 Гц), владение устройствами, vision-зоны,
  счёт. Комната = одна горутина (паттерн уже в `server/main.go`).
- **Клиент (TS + Babylon.js)** — рендер, инпут, интерполяция снапшотов
  (~100 мс в прошлом), автоогонь (клиент определяет «курсор на цели» и шлёт
  intent), DOM-оверлеи (HUD, hacker view).
- Транспорт: JSON поверх WS (MVP) → бинарный формат позже.
- Карта — данные (JSON), раздаётся сервером: `GET /api/map` — единый источник
  геометрии для сервера и клиента. Прокси: vite `/api` в dev, nginx `/api` в docker.

### 9.2. Wire protocol v0 (M1)

Клиент → сервер:
```jsonc
{"t":"join","name":"...","cls":"sniper|assault|heavy|hacker","team":-1} // team: -1=авто; 0|1=просьба (уважается, если не создаёт перекос ≥2); name уникально в комнате (дубликат → суффикс -2, -3…)
{"t":"input","seq":1,"keys":{"w":1,"a":0,"s":0,"d":1,"interact":0},"yaw":1.2,"pitch":-0.1} // ~30/с
{"t":"fire","yaw":1.2,"pitch":-0.1}                              // intent автоогня
{"t":"respawn","cls":"assault"}                                  // после таймера смерти
```

Сервер → клиент:
```jsonc
{"t":"welcome","id":7,"team":1,"tick":1234}
{"t":"snap","tick":1300,"now":169...,"players":[{"id":7,"name":"...","team":1,"cls":"assault","x":1,"y":2,"z":3,"yaw":0,"pitch":0,"hp":125,"alive":true,"safe":false}],"scores":[24,31],"timeLeft":342}
{"t":"shot","by":7,"hit":9,"from":[1,2,3],"to":[4,5,6]}          // трассер/киллфид; hit может быть null
{"t":"death","by":9,"respawnAt":169...}                          // жертве
{"t":"team","team":1}                                             // авто-ребаланс перекинул игрока (респаун на новой базе)
{"t":"matchend","winner":1,"scores":[50,31]}                     // winner: 0|1|-1 (ничья); далее сброс и новый матч
```

**Конвенции координат** (обязательны для обеих сторон):
- `x,y,z` — позиция **ног** игрока (глаза = y+1.6, тело AABB 0.6×1.8×0.6);
- `yaw` — вавилоновская LH-конвенция: 0 → смотрит в +Z, положительное значение — поворот по часовой стрелке (сверху), радианы;
- `pitch` — ±89°, положительный — вверх, радианы;
- `from/to` в shot — мировые координаты глаз стрелка и точки попадания (или дальнего конца луча при промахе).

Формат карты (`/api/map`):
```jsonc
{"name":"m1","bounds":[64,16,64],
 "colliders":[{"min":[0,0,0],"max":[64,1,64],"kind":"floor"}, ...],   // AABB, kind: floor|wall|stair
 "spawns":{"0":[[x,y,z],...],"1":[[x,y,z],...]},                      // по командам
 "props":[]}                                                          // M2+: устройства, кабели, сейфы
```

### 9.3. Движение (сервер, M1)

- Кинематический контроллер на AABB: скорость класса, гравитация 20 м/с²,
  autostep 0.55 м (лестницы = ступени-боксы), высота глаз 1.6 м, прыжка нет.
- Anti-cheat: сервер клампит скорость/частоту input, позиция только серверная.

### 9.4. Стрельба (M1)

- Клиент: автоогонь когда ray от камеры пересекает капсулу врага (или конус
  малости) → шлёт `fire` с направлением (не чаще темпа оружия).
- Сервер: валидирует темп; попадание засчитано, если луч **пересекает AABB
  цели — текущий или отмотанный на 4 тика (~133 мс, lag compensation под
  интерполяцию клиента ~100 мс)** — либо центр цели в конусе ~2° (мягкий
  bullet magnetism); LOS до центра цели должен быть чист. Ближайшая цель
  вдоль луча. История позиций — кольцо на 8 тиков на игрока.
  NB: проверка только «центр в конусе» (v0) отклоняла попадания в голову/
  грудь/ноги ближе ~10 м и по стрейфящимся целям — главный урок плейтеста M1.

### 9.5. Кибер-слой на сервере (M2+)

- Граф сети: устройства (хосты с CPU/NPU/RAM/NET) + каналы (кабель/радио).
- Планировщик: на каждый тик каждый процесс получает долю производительности
  пропорционально справедливому делению (round-robin слайсы); прогресс задач
  дискретный (у portscan «осталось 3.2 с при текущей загрузке»).
- Перерубленный кабель = удалённое ребро графа (восстановление — инженер? потом).
