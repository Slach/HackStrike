# HackStrike

Браузерная сессионная командная FPS-игра (WebGL) с двумя видами геймплея:
обычный FPS-вид и вид «хакера» с кибердекой, влияющий на окружение
(вдохновение — Dystopia mod). Клиент + авторитарный сервер, WebSocket, тик 30 Гц.

## Стек (решено 2026-11-14, см. docs/research/)

| Слой | Выбор |
|---|---|
| Клиент | TypeScript + Vite + Babylon.js 9.x |
| Сервер | Go 1.27 + `coder/websocket`, JSON-фреймы |
| Транспорт | WSS через тот же origin, что и клиент (nginx проксирует `/ws`) |
| Публикация | docker-compose + публичный zrok-шеринг, дальше itch.io |

## Скелет (текущее состояние)

Никакого геймплея — только проверка конвейера
`браузер → nginx(/ws) → zrok → game-server`:

- `server/` — одна комната, фиксированный тик 30 Гц, снапшоты всем клиентам,
  ping→pong для замера RTT. Состояние комнаты принадлежит одной горутине.
- `client/` — Babylon-сцена-заглушка (wireframe-пол, вращающийся «серверный
  рэк») + HUD: статус соединения, номер тика, число игроков, RTT, snaps/s.
  Вращение рэка привязано к серверному тику: остановилось — сеть, не рендер.

## Запуск

```bash
# всё, включая публичный zrok-шеринг (нужен ZROK2_ENABLE_TOKEN в .env):
docker compose up -d --build

# адрес шеринга:
docker compose logs zrok-share | grep -A2 zrok

# локально без zrok (клиент на http://127.0.0.1:9999):
docker compose up -d --build game-client game-server
```

Разработка без docker:

```bash
# терминал 1 — сервер (слушает :8080):
cd server && go run .

# терминал 2 — клиент (vite на :5173, /ws проксируется на :8080):
cd client && npm install && npm run dev
```

## Что смотреть в HUD

- **link** — ONLINE/OFFLINE с авто-reconnect (backoff до 8 c)
- **snaps/s** — должно быть ~30; через zrok это главный индикатор живости туннеля
- **rtt** — RTT до сервера (ping каждые 5 c)
